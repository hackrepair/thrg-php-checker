# PHP Checker 1.2.8-prerelease — pre-release

Prepared November 14, 2026 on `release/1.2.8`. This pre-release is on the `release/1.2.8` branch and has not been tagged or published.

## Changes

- Separate known compatibility impact from execution evidence, code origin and scan coverage. Logging, activation, filename hints and bundled origin cannot establish that a fatal path is harmless.
- Separate errors in code that appears to run at load ("Likely to fail on load", red "Hold off" banner) from fatal-mapped errors that only matter if the code runs ("May fail when used", review banner).
- Keep unknown-impact errors visible for review. Startup analysis identifies possible files and paths without claiming whole-program execution coverage.
- Preserve aggregate counts before limiting detailed findings, retain coverage-gap reasons, and require refreshed evidence when an older cache lacks required checks.
- Validate syntax without executing scanned source. A host parser failure marks incomplete coverage only when the server runs at least the target PHP; older servers skip the check instead of proving an error on a different PHP target. Source PHPCS suppressions do not hide compatibility findings; empty files scan normally.
- Align live summaries, plain-text downloads, HTML/plain-text emails, saved history and update checks. Incomplete evidence and rule changes cannot create a misleading resolved count or guaranteed fix claim.
- Remove the GitHub updater, the bundled Plugin Update Checker library (and its Parsedown copy), the View details companion tab and the GitHub-only edition. The plugin is built for WordPress.org only.
- Refresh single-component rescan results, keep grading notices visible and synchronize release metadata.

## Upgrade notes

Older scan results may request a refresh. New scans use classification version 4 and scan-evidence policy 2. Saved snapshots retain their original recorded classifications, subject to the existing bounded history retention.

The ZIP uses `thrg-php-checker/thrg-php-checker.php` and has no external updater. A copy installed earlier from a GitHub ZIP uses `thrg-php-checker/index.php`, so installing this build changes the plugin entry path and requires reactivation.

Static analysis does not replace testing important workflows on the intended PHP version. Complete coverage means the recorded static checks completed, not that every runtime path was exercised.

## Validation

The grading baseline passed 375 assertions on PHP 7.4.33, 8.2.33, 8.3.36, 8.4.11 and 8.5.7. Final candidate validation and package fingerprints are recorded in the local release preparation document.
