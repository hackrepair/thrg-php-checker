# PHP Checker 1.2.7

Local prerelease on branch `prerelease-1.2.7` (cut from `prerelease-1.2.6`). Not pushed, not released. Ships after 1.2.6.

## Highlights

- **A graded scale instead of a flat "Incompatible".** Each plugin and theme gets one of seven grades, worst first: *Breaks on load*, *Likely to break*, *Review: fallback code*, *Review: bundled library*, *Minor changes*, *Deprecation warnings*, *Compatible*. A component takes the worst grade of its counted findings. The stored verdict (`breaks`, `warnings`, `partial`, `ok`) is unchanged; the grade is stored alongside it.
- **Where the code sits.** Findings now record their scope (top of a file, class body, conditional, or inside a function), a fallback reason when the code only runs on a path modern servers seldom take, and a legacy file-name hint. Fallback paths recognised: the else branch of a `function_exists()`/`extension_loaded()` check, a branch that runs only when a feature is missing, the right side of `check || call`, a function called only from such branches, a call gated by a legacy resource string (`'mysql link' == $type && mysql_ping()`), and a legacy `mysql_*`/`mcrypt_*`/`ereg_*` branch next to its modern `mysqli_*`/`openssl_*`/`preg_*` replacement.
- **Breaks on load, carefully.** Grade 1 needs a removed function, constant or class (or a syntax change) at the top of a file or in a class body, in a file that certainly loads at startup: the main plugin file, a theme's `functions.php`, or a file they include at the top level with a literal path. Anything the scanner cannot read with certainty is never graded 1.
- **"Loads on PHP X on this site".** When the component is active, the server already runs the target PHP or newer, and WordPress has not paused it after a fatal error, the card says so. With the runtime log turned on this also lowers "Likely to break" to "Review: fallback code". It never lowers "Breaks on load". Fatal errors do not appear in the runtime log, so the check uses WordPress's own recovery-mode pause list instead.
- **Calmer banner.** The red "Hold off" banner appears only when an *active* component is graded 1 or 2. Inactive components and review items get a neutral "Review before upgrading" banner.
- **Filters:** "Will likely break" (grades 1-2) and "Needs a look" (grades 3-5).
- **WordPress.org fix check:** a newer version counts as "fatal errors fixed" when only review items (grade 4 or better) remain. Update pre-scan results store their grade.
- **Email and text report** show each component's grade and the "loads on this site" label.

## Old results

Results saved before 1.2.7 have no scope information. They grade as "Likely to break" (own code), "Review: bundled library" or "Minor changes" until the next scan, and are never graded "Breaks on load".
